# 直接视觉观察

第一次 Brain 决策附带原图时，直接查看图像并完整记录可见证据。后续普通 Brain 决策不再附带原图，应依据已经记录的视觉证据和工具结果继续推理；确有必要时，可以请求 `visual_reanalysis` 对一个具体目标进行复查。

在第一次 Brain 决策中，一边选择下一步定位动作，一边将可观察证据记录到顶层 `visual_analysis` 字段。该字段是便于审计的观察记录，不是限制推理的信息中间层。此后的每次决策都将 `visual_analysis` 和 `visual_updates` 设为 null。`visual_reanalysis` 返回的证据会自动合并到紧凑状态，不要再把它复制或改写为视觉更新。初次观察要全面且具体。像"城市街道"这类泛泛描述是弱线索，除非画面中没有更好的线索。

诸如 `{year} Google`、`{year} Baidu`、`@ {year} Google` 或 `@ {year} Baidu` 这样的街景水印是采集方叠加层，不是有用的文本证据；不要返回它们。

## 实体归属

当图像中包含多个店面、招牌、POI、电话号码或地址时，要按可见的物体或店面对其文本分组。除非电话号码在视觉上位于同一块招牌、门面、橱窗、海报或店面区域，否则不要把电话号码归属于某个 POI。

使用 `observed_entities` 来表示这些分组。如果某个电话号码可见但其所属店面不明确，请创建一个单独的 `phone` 实体，并在 `region_hint` 中注明"未归属的可见电话/文本"，而不是将其挂到附近的 POI 上。

如果某个全球或全国知名的地标/建筑可以直接从图像中辨认出来，请将其表示为一个 `entity_type: "landmark"` 的 `observed_entities` 条目。这包括诸如天安门、白宫、人民大会堂、埃菲尔铁塔、中正纪念堂或其他广为人知的建筑。

只有当识别建立在可见证据之上（独特的建筑形态、轮廓、门面、纪念碑布局、可见的名字片段、符号或铭牌）时才使用 `landmark`。如果它只是与某个著名地标相似，请在 `visual_cues` 和 `reasoning_notes` 中描述这种相似性，而不是命名一个地标实体。

## 线索类型层级

使用以下精确的 `cue_type` 取值：

| 线索类型 | 适用范围 |
| --- | --- |
| `driving_side` | 可见的行车方向、车道侧向、车流方向 |
| `licence_plate` | 车牌格式、颜色、字符样式、安装方式 |
| `road_marking` | 车道线、箭头、人行横道、停止线、路面喷涂文字 |
| `road_sign` | 交通标志——观察形状、颜色、边框、符号样式、文字以及内部元素的数量/布局（如行人标志上的条纹数），而不只是标志类型 |
| `crossing` | 人行横道、信号灯、路口几何形态 |
| `bollard` | 交通隔离柱、护栏、锥桶、导向标 |
| `guardrail` | 道路护栏和路边屏障 |
| `utility_pole` | 电力/电话线杆、架空线、电杆布局 |
| `lamp_post` | 路灯样式、高度、间距 |
| `kerb` | 路缘或人行道边缘的样式、颜色、材质 |
| `bin` | 垃圾桶或回收容器 |
| `taxi` | 出租车颜色、顶灯、涂装标识 |
| `bus` | 公交车涂装、线路显示、站点 |
| `architecture` | 建筑材料、屋顶形式、立面风格、密度 |
| `vegetation` | 树木、植物、花园、与气候相关的植被 |
| `terrain` | 坡地、山地、海岸线、河流、湖泊、平坦度 |
| `soil` | 泥土、碎石、沙地、铺装、裸露地面 |
| `climate` | 天气、湿度、积雪、干燥度、光照条件 |
| `language_script` | 文本中可见的文字系统和语言 |
| `urban_form` | 街道密度、开发类型、道路宽度、街区形态 |
| `landmark` | 显著的高塔、纪念碑、独特构筑物 |
| `bridge` | 桥梁、立交、高架道路 |
| `road` | 道路材质、宽度、车道数、路况 |
| `infrastructure` | 排水口、井盖、交通信号灯、线缆 |
| `coverage` | 地表覆盖，如草地、混凝土、水面、森林 |
| `follow_car` | 可见的采集车或车流指示 |
| `rural_building` | 农舍、谷仓、棚屋、乡村建筑 |
| `fire_hydrant` | 消防栓样式、颜色、位置 |
| `rock_wall` | 石墙、崖壁、挡土墙 |
| `other` | 不属于其他类型的独特线索 |

## 交通标志细节观察

交通标志是高价值线索，因为其内部视觉细节因国家/地区而异。对每一个可读的交通标志，要描述其具体的视觉特征，而不只是类型。将每个不同的标志作为独立的 `visual_cues` 条目上报，`cue_type` 为 `"road_sign"`，具体细节写入 `text`。

- **人行横道标志**：准确数出斑马线条数（如 3、4、5、7、8 条）；注意条纹是否被虚线或单条横线替代，或是否缺失；描述人形图案——是否系腰带（及其高度）、是否戴帽子、是否为方头、是女性还是男性剪影、鞋子细节、头部是否残缺、精细程度以及衣着；注意标志形状（三角形、五边形、矩形）、背景色以及任何彩色边框。
- **停止/让行标志**：颜色、形状、边框、文字的语言和确切措辞。
- **方向/ Chevron（V 形）标志**：配色方案、字体、箭头样式、V 形符号的数量和密度。
- **城镇入口标志**：字体、版式、颜色、语言、名称后缀风格。
- **里程标/高速公路盾牌**：颜色、形状、编号格式、材质、安装方式。
- **其他警告/管制标志**：形状（三角形/菱形/圆形）、边框颜色、背景颜色、符号样式、任何文字。

优先使用精确的计数和样式描述，而非泛泛的标签。"5 条条纹、人物系着腰带且重心偏低的行人标志"远比"人行横道标志"有价值。

## 优先级指南

优先记录具有地理区分度的线索。不要把可读文本视为唯一有价值的证据。

- 精确记录可见的命名锚点：地名、商户名、地址、道路名称、邮政编码以及可直接辨认的地标。
- 独立记录最强的非文本区域性线索：行驶方向、道路标线和标志设计、市政基础设施、车辆和车牌样式、建筑和城市形态、植被、地形、气候以及地表覆盖/采集特征。
- 对于建筑、植被、地形以及文化或商业环境，要说明具体可观察的属性及其可能暗示的地理对比。例如，描述屋顶材质、立面处理、街道密度、作物类型、山地/滨海环境或道路设施样式；不要只写"欧式建筑"或"热带植被"。
- 清晰的文本锚点可以支撑后续的细粒度调查，但非文本线索仍必须保留，因为它们建立国家/地区先验，并且可能与文本推导的候选位置相矛盾。

## 不确定性处理

- 明确报告不确定性。
- 如果文字只部分可见，保留可见字符并降低置信度。
- 逐字符抄录可见文字；除非在备注中确有必要，否则不要翻译。
- 独特的细节比明显的场景标签更有价值。
- 宁要若干精确线索，不要大量泛泛线索。
- 在 `reasoning_notes` 中将命名/文本锚点与区域性视觉线索分开。当图像没有可靠的文本锚点时，说明哪些非文本线索有助于提出或排除国家/地区，哪些过于泛化而无法使用。
- **可定位性估计**：提取线索后，评估这张图像现实上能够支持的最大粒度。如果图像包含命名的视觉锚点（OCR 地名文本、POI 名称、地标、地址、道路标志），则根据具体程度将 `max_expected_granularity` 设为 `street`、`city` 或更细。如果图像只包含泛化的场景线索（建筑、植被、交通模式）而没有文本或命名锚点，则设为 `country` 或 `continent`。`score` 反映对这一上限的置信度（0.0-1.0）。该估计帮助推理智能体合理分配搜索精力。

## 视觉分析字段

在 BrainDecision 中使用下面的 `visual_analysis` 字段结构。第一次决策必须包含所有子字段；某个列表字段没有观察结果时使用空数组。
```json
{
  "visual_analysis": {
  "scene_summary": "对整个场景的 2-3 句事实性描述",
  "visual_cues": [
    {
      "cue_type": "上述层级中的精确线索类型",
      "text": "带有具体细节的特定可观察线索",
      "confidence": 0.0
    }
  ],
  "ocr_results": [
    {
      "text": "逐字符抄录的精确可见文本",
      "language": "检测到的语言或 null",
      "confidence": 0.0
    }
  ],
  "observed_entities": [
    {
      "id": "稳定 id，例如 ent_left_store",
      "entity_type": "poi|landmark|phone|address|sign|vehicle|other",
      "name": "可见的 POI/商户/招牌名称、直接辨认出的地标名称，或 null",
      "text_items": ["在视觉上隶属于同一实体的所有文本"],
      "phones": ["仅在视觉上隶属于同一实体时才填入的电话号码"],
      "region_hint": "该实体在图像中出现的位置",
      "confidence": 0.0
    }
  ],
  "search_queries": [
    "2-4 条结合最独特线索的简洁网页搜索查询"
  ],
  "reasoning_notes": [
    "哪些可直接观察、哪些不确定、哪些线索最有用"
  ],
  "locatability": {
    "max_expected_granularity": "coordinates|poi|street|city|region|country|continent",
    "score": 0.0,
    "rationale": "简要解释为什么这是给定可见锚点和线索下的最大预期精度"
  }
  }
}
```

后续决策将 `visual_updates` 设为 null。如果已记录证据不足，请通过 `visual_reanalysis` 提出一个具体问题，并明确目标图像区域或对象；其结果会自动合并到状态中。
